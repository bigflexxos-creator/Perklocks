## Root Cause — Line-Level

**`_build_pick` was NOT the wipe source.**  Proven in-memory
(`/tmp/trace_bp.py`): feeding `_build_pick` a 12-key factor dict
(including the 5 `(norm)` numeric evidence keys + 5 human-readable
string keys + 2 provenance `__`-keys) returns a pick whose `factors`
field carries all 12 keys.  Alignment component computes to 54.9 (not
the len<2 default of 50), confirming the (norm) values reach
`compute_lock_score` unmangled.

**The actual "wipe" was a legacy retirement artifact.**  Every current
CFB v4 row (74 rows in the current window) had already been
**quarantined by `scripts.maintenance.retire_cfb_for_regen`** which
retires v4 CFB rows lacking a `cfb_engine_version` stamp so a future
production cycle can regenerate them:

    retirement_reason ∈ {
      cfb_pre_fix_regen_r1_r2_r3           (48 rows),
      cfb_pre_fix_stale_v2_factor_level    (10 rows),
      cfb_pre_fix_empty_factors_high_lock_v2026_06_11 (8 rows),
    }

Because the retired rows were emitted BEFORE the R1 factor-persistence
merge landed in `sports_engine.py` (L3343-3345 · L2530-2562), they
have `factors: {}`.  The R1 merge is now correctly in place for
FUTURE emissions — proven by the in-memory `_build_pick` test — but
those retired rows never got regenerated by a production refresh cycle
(no live CFB provider data ran in this environment).
